# Project Governance

**Kwegatta** is an open-source initiative dedicated to fostering student innovation and peer learning across universities and tech hubs in Uganda and East Africa. It is governed as a community-driven open-source project aligned with the **Digital Public Goods Standard**.

---

## 1. Project Ownership

Kwegatta is not owned by any single corporation. The codebase and documentation are published under the permissive **MIT License**, ensuring permanent community access, transparency, and freedom to fork, study, and improve the software.

## 2. Decision-Making Process

We use a consensus-seeking model grounded in open discussion:

### Principles
1. **Student & Builder Utility First**: Decisions must prioritize helping students connect, find complementary co-founders, and learn practical skills.
2. **Open-Weight AI Exclusivity**: We strictly maintain the hard rule that only open-weight models (specifically `gemma-4-31b-it`) may be utilized. Proposals to integrate proprietary closed models will be rejected to preserve software transparency and sovereignty.
3. **Privacy by Design**: Sensitive user data (like phone numbers) will never be harvested or exposed for bulk crawling.
4. **Open Public Discourse**: Feature debates, architecture proposals, and roadmaps must be discussed publicly in GitHub Issues and Pull Requests.

### Decision Hierarchy
* **Minor Changes** (Bug fixes, UI polish, documentation, typo corrections): Any core maintainer may approve and merge after automated build and lint checks pass.
* **Significant Changes** (Data schema updates, AI prompt changes, new campus support, privacy model alterations): Require discussion on an RFC issue and approval from at least two maintainers.
* **Tie-Breaking**: If consensus cannot be reached, the Lead Maintainer (Saifuddin Ahmed) makes the final decision with documented justification.

---

## 3. How to Become a Maintainer

We actively mentor and welcome contributors from student builder communities into leadership:

1. **Contributor**: Submits bug reports, feature suggestions, or pull requests that adhere to `CONTRIBUTING.md`.
2. **Reviewer**: Consistently helps review community pull requests, tests edge cases, and provides helpful, constructive feedback.
3. **Core Maintainer**:
   * Has contributed multiple sustained pull requests (features, documentation, or infrastructure).
   * Demonstrates a deep understanding of Kwegatta's architecture, Primer UI standards, and open-weight model constraints.
   * Upholds the Contributor Covenant Code of Conduct.
   * Existing maintainers vote to extend maintainer privileges with commit access.

---

## 4. Conflict Resolution

Disagreements will be handled through civil, constructive dialogue in public GitHub threads. If personal or code-of-conduct conflicts arise, community members may contact the project leads confidentially at `conduct@kwegatta.org`.
